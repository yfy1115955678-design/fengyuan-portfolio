01 / PROBLEM

产品开发需要连续判断，也需要保留每次判断的来路。

在真实新品开发中，市场数据、评论、竞品、产品要求、BOM、供应商信息和评审结论往往分散在不同工具、表格、文档与 AI 对话中。问题不只在于整理耗时，更在于阶段之间容易丢失证据、约束和决策上下文。

Nextly 2.0 将这些判断放入同一条产品开发链路：每一步只回答一个核心问题，明确输入、输出、证据和下一步；当市场需求与落地边界冲突时，系统保留冲突并要求人工处理。

数据边界：商品、评论、报价等原始数据仍由影刀、卖家精灵或其他外部工具获取；AI 对已获得的数据进行清洗、结构化、分析与影响判断。

值得继续吗？

Review · Gate P
03 / AGENT SYSTEM

主控负责路由，专业 Agent 负责执行。

用户主要与 Nextly 主控交互。主控判断任务属于哪个阶段，调用对应的专业 Agent 与 Skill，再把输出、证据和状态变化写回统一的 Product State；专业 Agent 不被拆成多个并列聊天窗口。

01 / ORCHESTRATE

主控 Agent

识别任务、解释当前状态、路由专业 Agent，并给出下一步建议。

02 / EXECUTE

Agent + Skill

Agent 回答“谁负责”，Skill 回答“怎么做”；市场扫描、VOC、BOM、风险核验等能力可以复用。

03 / TRACE

Run Trace

记录 Main → 专业 Agent → Skill → State Update，保留输入、输出、证据与受影响模块。

04 / GOVERN

Human Gate

AI 不能自动越过关键确认；继续、修改、暂停都由人决定并写入 Decision Log。

04 / CONFLICT LOOP

发现冲突时，先阻断，再修订。

演示项目中，市场研究提出“整机洗碗机安全”，落地验证发现泵体与 PCB 无法满足这一表述。系统不会把冲突藏在结果里，也不会直接覆盖原判断。

“待复核”意味着什么？

证据、冲突或影响范围尚未完成确认。相关阶段会显示待复核状态，评审页汇总仍未关闭的风险；高风险问题可以阻断 Gate P。历史 Evidence、Version、Diff 与 Decision Log 保留，不反向改写已经发生的事实。

05 / VERSION & REFRESH

新数据只影响需要重算的部分。

→
DIFF生成版本差异

PARTIAL RERUN人工确认后局部复核

没有实质变化时停止传播；有变化时，把受影响的 Opportunity 或 Product Definition 标记为 STALE，再提示需要复核的下游模块。
